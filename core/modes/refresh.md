# refresh 모드

규칙과 어휘를 최신 공식 문서와 현재 모델의 실제 효과에 맞춰 갱신한다. 에이전트는 변경안을 만들고 적용할 뿐이고, 무엇을 바꿀지는 사람이 승인한다. 사람용 전체 절차는 `MAINTAINING.md`에 있다.

## 원칙

- 사람이 승인하기 전에는 `core/`의 어떤 파일도 수정하지 않는다.
- 모든 변경안에는 근거를 단다. 문서 근거는 원문 인용(15단어 이하)과 URL, 평가 근거는 결과 파일 경로와 지표.
- 커밋과 푸시는 하지 않는다. 사람이 한다.
- 웹 문서를 읽을 수 없는 환경이면 시작하지 않고 그 사실을 알린다.

## 판정 표

| 문서 | 평가 | 판정 |
|---|---|---|
| 변화 없음 | 통과 | 유지. `verified` 날짜만 갱신 |
| 규칙과 충돌하는 변화 | - | 수정 또는 폐기 |
| 새 권고 | - | 신규 |
| 변화 없음 | 효과 없음 (effects) 또는 해당 규칙 관련 케이스 실패 | 수정 또는 폐기 |

## 절차

### 단계 A. 기준선 평가와 문서 대조 (사람의 1단계 명령 후)

1. 기준 모델을 정한다. `--model`이 있으면 그 값, 없으면 현재 실행 중인 모델 ID.
2. `core/modes/eval.md`로 전체 평가를 실행한다. 결과 종류는 `baseline`이다.
   → `evals/results/<오늘>-<모델>-baseline.md`
3. `core/sources.md`의 출처마다 URL을 다시 읽고, "핵심 주장 스냅샷"의 각 줄이 여전히 맞는지, 바뀌었는지, 사라졌는지 확인한다. 스냅샷에 없는 새 권고도 찾는다. 모델별 가이드 목록에 새 모델 페이지가 생겼으면 새 출처 후보로 올린다.
4. 판정 표에 따라 항목마다 판정을 내리고 변경안 파일을 쓴다.
   → `refresh/<오늘>-proposal.md`
5. 사람에게 변경안 파일 경로와 요약(항목 수, 판정별 개수)을 알리고 멈춘다.

변경안 파일 형식:

````markdown
# refresh 변경안 2027-01-05 (기준 모델: claude-opus-5-5)
기준선: 검출률 94% · 오탐 0 · 모범 점수 88 · 프레임 적중 6/6 · 효과 있음 9/10
기준선 파일: evals/results/2027-01-05-claude-opus-5-5-baseline.md

| ID | 대상 | 판정 | 근거 |
|---|---|---|---|
| P-01 | R-TOL-003 | 수정 | S-01 변경: "(원문 인용)" |
| P-02 | F-CRT-01 | 수정 | E-01 효과 없음 (A 2/3, B 2/3) |
| P-03 | (신규) R-AGT-007 | 신규 | S-03 새 권고: "(원문 인용)" |
| P-04 | S-05 (신규 출처) | 신규 | 새 모델 가이드 페이지 (URL) |
| P-05 | 나머지 44개 | 유지 | 변화 없음, 평가 통과 |

## P-01 상세
- 대상 파일: core/rules/tools.md
- 변경 전:
  (현재 내용)
- 변경 후:
  (제안 내용)
- 영향받는 평가 케이스: C-01

## 결정 방법
채팅으로 항목별 결정을 알려주세요. 예: "P-01, P-03 승인. P-02 보류."
언급하지 않은 항목은 보류로 처리합니다. 유지 항목(P-05 등)은 승인하지 않아도 날짜만 갱신합니다.
````

### 단계 B. 적용과 재평가 (사람의 승인 메시지 후)

1. 승인 메시지를 해석한다. "승인"은 반영, "보류"와 언급되지 않은 항목은 반영하지 않고 변경안 파일에 보류로 기록, "거절"은 반영하지 않고 사람이 준 이유를 기록한다.
2. 승인된 항목만 `core/` 파일에 반영한다. 폐기는 삭제하지 않고 `status: deprecated`, `deprecated_reason`, `replaced_by`(있으면)를 추가한다. 신규 규칙이나 어휘는 같은 카테고리의 다음 번호를 쓴다.
3. 전체 평가를 다시 실행한다. 결과 종류는 `after`다.
   → `evals/results/<오늘>-<모델>-after.md`
4. 기준선과 재평가의 요약 줄을 표로 비교해 보여준다.
5. 통과 기준을 못 넘거나 기준선보다 나빠진 지표가 있으면:
   - 원인 항목이 분명하면 (그 항목이 다루는 케이스만 나빠졌으면) 그 항목을 되돌리고 보고한다.
   - 원인이 분명하지 않으면 되돌리지 말고 상황을 보고하고 멈춘다. 항목을 하나씩 빼며 재평가하면 비용이 크기 때문에, 사람이 다음 행동을 정한다.
6. 사람에게 "확정해줘"를 기다린다고 알리고 멈춘다.

### 단계 C. 확정 (사람의 "확정해줘" 후)

1. `VERSION`을 올린다.
   - 유지와 날짜 갱신만 있으면 PATCH
   - 규칙, 어휘, 출처의 신규나 수정이 있으면 MINOR
   - 모드, 출력 형식, 채점 구조가 바뀌었으면 MAJOR
2. `CHANGELOG.md` 맨 위에 항목을 추가한다.
   ```markdown
   ## [1.1.0] 2027-01-05 · claude-opus-5-5
   ### 추가
   - R-AGT-007 ... (P-03)
   ### 수정
   - R-TOL-003 ... (P-01)
   ### 폐기
   - (없음)
   ### 평가
   - 기준선: (요약 줄) → 적용 후: (요약 줄)
   ```
3. `core/sources.md`의 `last_checked`를 오늘로, 바뀐 스냅샷 줄을 새 내용으로 고친다.
4. 유지 판정된 규칙과 어휘, 그리고 반영된 항목의 `verified`를 `<오늘> / <기준 모델>`로 고친다. 보류된 항목은 날짜를 바꾸지 않는다. 그래야 낡음 경고가 계속 남는다.
5. `adapters/generic/build.sh`를 실행해 붙여넣기용 어댑터를 다시 만든다.
6. 바뀐 파일 목록과, 사람이 실행할 커밋 명령을 알려준다 (`MAINTAINING.md` 6단계).
