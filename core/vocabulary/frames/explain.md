# 프레임 어휘: 설명·학습 (EXP)

모델이 용어를 늘어놓는 설명 대신, 상대가 실제로 이해하게 만드는 방식으로 바꾸는 프레임이다.

프레임 어휘는 태도를 바꿀 뿐 결과의 형태를 정하지 않는다.
항상 정밀 어휘(범위, 개수, 형식, 완료 기준)와 함께 쓴다.
단순 실행 요청(수정, 변환, 이름 바꾸기 등)에는 쓰지 않는다.

## F-EXP-01  소크라테스식 질문 / Socratic Questioning
- 의도: 설명, 학습
- 바뀌는 태도: 답을 바로 알려줌 → 질문으로 스스로 답에 이르게 함
- 쓸 때: 학습자가 개념을 체득해야 할 때, 신입 멘토링, 문제 풀이 연습
- 쓰지 말 때: 답이 급하게 필요할 때
- 대안: 빠른 이해가 목적이면 F-EXP-02 파인만 기법
- 함께 쓸 정밀 어휘: V-AUD-03, V-DON-01
- 템플릿: 너는 소크라테스식 튜터다. [주제]의 답을 바로 알려주지 말고, 한 번에 질문 하나씩 해서 내가 스스로 답에 이르게 해. 내가 틀리면 틀린 이유를 생각하게 하는 질문을 해. 내가 [완료 조건]을 말할 수 있으면 끝낸다.
- Before: 데이터베이스 인덱스가 뭔지 알려줘.
- After: 너는 소크라테스식 튜터다. 데이터베이스 인덱스의 원리를 바로 설명하지 말고, 한 번에 질문 하나씩 해서 내가 스스로 이해하게 해. 내가 "인덱스가 왜 쓰기 속도를 늦추는지"를 내 말로 설명할 수 있으면 끝내고 요약해 줘.

## F-EXP-02  파인만 기법 / Feynman Technique
- 의도: 설명, 학습
- 바뀌는 태도: 전문 용어로 된 정확하지만 어려운 설명 → 쉬운 말과 비유로 핵심만
- 쓸 때: 비전공자에게 기술 개념을 설명할 때, 내가 개념을 정말 이해했는지 점검할 때
- 쓰지 말 때: 전문가끼리 정밀한 사양을 논의할 때
- 대안: 독자가 실무자면 V-AUD-04 바로 실행할 담당자
- 함께 쓸 정밀 어휘: V-AUD-02, V-FMT-02, V-DON-01
- 템플릿: 파인만 기법으로 [개념]을 설명해. 전문 용어를 쓰면 바로 쉬운 말로 풀고, 일상 비유를 하나 들고, 마지막에 이해했는지 확인할 질문 하나를 해. [N]문단 이내로 써.
- Before: 쿠버네티스가 뭔지 설명해줘, 나 비전공자야.
- After: 파인만 기법으로 쿠버네티스를 설명해. 독자는 개발 경험이 없는 기획자다. 전문 용어를 쓰면 바로 쉬운 말로 풀고, 일상생활 비유를 하나 들어. 3문단 이내로 쓰고, 마지막에 이해했는지 확인할 질문 하나를 해.

## F-EXP-03  비전공 신입에게 / Explain to a New Hire
- 의도: 설명, 학습
- 바뀌는 태도: 설명하는 사람의 지식 수준에 맞춘 글 → 사내 맥락이 전혀 없는 사람 기준
- 쓸 때: 온보딩 문서, 사내 용어가 많은 업무를 처음 소개할 때
- 쓰지 말 때: 독자가 이미 팀의 맥락을 아는 경우
- 대안: 의사결정자용이면 V-AUD-02 비전공 임원
- 함께 쓸 정밀 어휘: V-AUD-03, V-FMT-04, V-DON-01
- 템플릿: 오늘 입사한 비전공 신입에게 [업무]를 설명한다고 생각해. 사내 약어는 처음 나올 때 풀어 쓰고, 왜 이 일이 필요한지 먼저 말한 뒤 첫 주에 할 일 [N]개로 끝내.
- Before: 우리 팀 배포 프로세스 설명 자료 만들어줘.
- After: 오늘 입사한 비전공 신입에게 우리 팀 배포 과정을 설명한다고 생각하고 써. 사내 약어는 처음 나올 때 풀어 쓰고, 배포를 왜 이렇게 나눠 하는지 먼저 한 문단으로 말해. 마지막은 첫 주에 직접 해볼 일 3개로 끝내. `<프로세스>`(배포 단계)`</프로세스>`
