# 프레임 어휘: 분석 (ANL)

모델이 현상을 나열하는 데서 멈추지 않고, 구조적으로 원인과 판단까지 가게 만드는 프레임이다.

프레임 어휘는 태도를 바꿀 뿐 결과의 형태를 정하지 않는다.
항상 정밀 어휘(범위, 개수, 형식, 완료 기준)와 함께 쓴다.
단순 실행 요청(수정, 변환, 이름 바꾸기 등)에는 쓰지 않는다.

## F-ANL-01  5 Whys
- 의도: 분석
- 바뀌는 태도: 눈에 보이는 증상을 원인으로 보고 끝냄 → "왜"를 반복해 근본 원인까지 내려감
- 쓸 때: 장애, 지표 하락, 반복되는 문제의 원인 분석
- 쓰지 말 때: 원인이 여러 갈래로 동시에 작용해 한 줄 사슬로 설명할 수 없을 때
- 대안: 원인이 여러 갈래면 F-ANL-02 MECE
- 함께 쓸 정밀 어휘: V-EVD-04, V-RSN-01, V-DON-01
- 템플릿: [문제]의 원인을 5 Whys로 분석해. 각 단계의 "왜"에 대한 답마다 근거가 되는 자료를 붙이고, 자료로 확인되지 않는 단계는 "추정"으로 표시해. 근본 원인에 대한 재발 방지책 [N]개로 끝내.
- Before: 이번 배포 장애 왜 났는지 정리해줘.
- After: 이번 배포 장애의 원인을 5 Whys로 분석해. 각 "왜"의 답마다 아래 로그나 타임라인에서 근거를 붙이고, 근거가 없는 단계는 "추정"으로 표시해. 증상과 근본 원인을 구분해서 쓰고, 근본 원인에 대한 재발 방지책 3개로 끝내. `<타임라인>`(로그)`</타임라인>`
- 효과 평가: E-05

## F-ANL-02  MECE
- 의도: 분석
- 바뀌는 태도: 겹치고 빠지는 항목이 섞인 나열 → 서로 겹치지 않고 빠짐없이 나눈 구조
- 쓸 때: 문제를 쪼개 원인 후보를 찾을 때, 보고서 목차를 짤 때
- 쓰지 말 때: 하나의 원인 사슬을 깊게 파야 할 때
- 대안: 깊게 파야 하면 F-ANL-01 5 Whys
- 함께 쓸 정밀 어휘: V-FMT-01, V-SCP-01
- 템플릿: [문제]를 MECE로 나눠. 첫 단계 분류 기준을 먼저 밝히고, 하위 항목이 서로 겹치지 않고 합치면 전체가 되는지 확인해. 각 항목마다 확인할 데이터를 붙여.
- Before: 매출 줄어든 이유 정리해줘.
- After: 이번 달 매출 감소를 MECE로 나눠. 먼저 "매출 = 방문자 수 × 구매 전환율 × 객단가"처럼 첫 단계 분류 기준을 밝혀. 하위 항목이 서로 겹치지 않고 합치면 전체가 되는지 확인하고, 각 항목마다 확인할 지표를 붙여.

## F-ANL-03  가설 기반 분석 / Hypothesis-driven
- 의도: 분석
- 바뀌는 태도: 데이터를 다 훑고 나서 결론을 찾음 → 가설을 먼저 세우고 검증할 데이터를 고름
- 쓸 때: 데이터가 많고 시간이 짧을 때, 분석 계획을 세울 때
- 쓰지 말 때: 가설을 세울 사전 지식이 전혀 없는 탐색 단계
- 대안: 탐색 단계면 F-ANL-02 MECE로 먼저 나누기
- 함께 쓸 정밀 어휘: V-RSN-04, V-EVD-04, V-SCP-03
- 템플릿: [문제]에 대해 가능성이 높은 가설 [N]개를 먼저 세워. 각 가설마다 맞다면 보여야 할 데이터와 틀렸다면 보여야 할 데이터를 적고, 아래 자료로 검증 가능한 것부터 판정해.
- Before: 이번 달 이탈률이 왜 올랐는지 봐줘.
- After: 이번 달 이탈률 상승에 대해 가능성이 높은 가설 3개를 먼저 세워. 각 가설마다 맞다면 보여야 할 지표 변화와 틀렸다면 보여야 할 변화를 적고, 아래 지표로 판정해. 판정할 수 없는 가설은 추가로 필요한 데이터를 적어. `<지표>`(데이터)`</지표>`
