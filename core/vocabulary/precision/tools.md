# 정밀 어휘: 도구 (TOL)

에이전트의 도구 사용을 조건과 순서로 정하는 어휘다. 주로 에이전트 지침에 쓴다.

## V-TOL-01  ~일 때 [도구]를 써 / Use X when
- 상황: 도구를 너무 자주 또는 너무 드물게 쓸 때
- 약한 표현: "필요하면 검색해", "반드시 검색해"
- 강한 표현: "답이 사내 규정에 달려 있을 때 search_docs를 쓴다. 일반 상식 질문에는 쓰지 않는다."
- 효과가 있는 이유: 사용 조건과 비사용 조건이 함께 있어야 과잉 호출과 누락이 함께 줄어든다
- 업무 예시: 데이터 - "수치를 인용할 때만 run_sql로 확인한다."
- 관련 규칙: R-TOL-001, R-TOL-002
- verified: 2026-11-21 / claude-opus-5-5

## V-TOL-02  독립 작업은 병렬로 / In parallel
- 상황: 서로 관계없는 조회나 작업이 여러 개일 때
- 약한 표현: (언급 없음)
- 강한 표현: "서로 결과를 기다리지 않는 조회는 동시에 실행하고, 앞 결과가 필요한 것만 순서대로 실행해."
- 효과가 있는 이유: 대기 시간이 줄고 순서가 필요한 호출은 지켜진다
- 업무 예시: 코딩 - "여러 파일을 읽을 때는 한 번에 읽어."
- 관련 규칙: R-TOL-004
- verified: 2026-11-21 / claude-opus-5-5

## V-TOL-03  값을 추측하지 말고 확인해 / Don't guess parameters
- 상황: 도구 호출에 필요한 값이 빠질 수 있을 때
- 약한 표현: (언급 없음)
- 강한 표현: "도구에 넣을 값이 없으면 추측하지 말고 사용자에게 묻거나 조회 도구로 확인해."
- 효과가 있는 이유: 잘못된 값으로 실행되는 사고를 막는다
- 업무 예시: RAG - "주문번호가 없으면 먼저 물어보고 조회해."
- 관련 규칙: R-TOL-004
- verified: 2026-11-21 / claude-opus-5-5

## V-TOL-04  이미 아는 것인지 먼저 판단해 / Check before searching
- 상황: 검색 도구가 있어 모든 질문마다 검색하려 할 때
- 약한 표현: "모르면 검색해"
- 강한 표현: "학습 이후 바뀌었을 수 있는 정보(가격, 일정, 최근 발표)일 때만 검색하고, 변하지 않는 개념은 바로 답해."
- 효과가 있는 이유: 불필요한 검색이 줄어 비용과 지연이 준다
- 업무 예시: 문서 - "용어 정의는 검색 없이, 최신 정책은 검색해서."
- 관련 규칙: R-TOL-006
- verified: 2026-11-21 / claude-opus-5-5
