# 정밀 어휘: 형식 (FMT)

결과물의 모양을 정해 바로 쓸 수 있게 만드는 어휘다.

## V-FMT-01  표로 / As a table
- 상황: 여러 항목을 같은 기준으로 비교하거나 나열할 때
- 약한 표현: "정리해줘"
- 강한 표현: "항목, 현재 상태, 문제, 제안 네 열의 표로 정리해."
- 효과가 있는 이유: 열을 지정하면 항목마다 같은 정보가 빠짐없이 채워진다
- 업무 예시: 데이터 - "지표, 이번 달, 지난달, 변화율 열의 표로."
- 관련 규칙: R-OUT-001
- verified: 2026-11-21 / claude-opus-5-5

## V-FMT-02  N개 문단의 산문으로 / In N prose paragraphs
- 상황: 글머리표가 아니라 읽히는 글이 필요할 때
- 약한 표현: "마크다운 쓰지 마"
- 강한 표현: "자연스럽게 이어지는 3개 문단의 산문으로 써."
- 효과가 있는 이유: 금지보다 원하는 형태를 말할 때 형식이 더 잘 지켜진다
- 업무 예시: 문서 - "사내 소식지 기사를 4개 문단으로."
- 관련 규칙: R-EMP-003, R-OUT-002
- verified: 2026-11-21 / claude-opus-5-5

## V-FMT-03  이 스키마의 JSON으로 / JSON matching
- 상황: 결과를 프로그램이 받아 처리할 때
- 약한 표현: "JSON으로 줘"
- 강한 표현: "다음 스키마를 따르는 JSON만 출력해: {\"category\": string, \"urgency\": \"low\"|\"high\", \"summary\": string}"
- 효과가 있는 이유: 필드와 허용값을 고정하면 파싱 오류가 줄어든다. 가능하면 구조화 출력 기능을 함께 쓴다
- 업무 예시: RAG - "답변과 근거 문서 번호를 JSON으로."
- 관련 규칙: R-OUT-001, R-LEG-001
- verified: 2026-11-21 / claude-opus-5-5

## V-FMT-04  결론 먼저 / Bottom line up front
- 상황: 바쁜 독자가 첫 부분만 읽고 판단해야 할 때
- 약한 표현: "보고서 써줘"
- 강한 표현: "첫 문장에 결론을 쓰고, 그다음에 근거를 중요한 순서로 써."
- 효과가 있는 이유: 결론 위치를 고정하면 배경 설명이 앞을 차지하지 않는다
- 업무 예시: 데이터 - "분기 실적 요약의 첫 문장을 '목표 대비 몇 %'로 시작해."
- 관련 규칙: R-OUT-001, R-CTX-003
- verified: 2026-11-21 / claude-opus-5-5
- effect: none (claude-opus-5-5, 2026-11-21, A 3/3, B 3/3). 어휘 없이도 기준을 대부분 충족해 차이가 2 미만이었다

## V-FMT-05  복사 가능한 코드 블록으로 / In a copyable block
- 상황: 결과를 다른 곳에 그대로 붙여 넣어 써야 할 때
- 약한 표현: "프롬프트 만들어줘"
- 강한 표현: "완성된 프롬프트만 코드 블록 하나에 넣어. 설명은 블록 밖에 써."
- 효과가 있는 이유: 붙여 넣을 부분과 설명이 섞이지 않는다
- 업무 예시: 코딩 - "실행할 명령어를 한 블록에 하나씩."
- 관련 규칙: R-OUT-001
- verified: 2026-11-21 / claude-opus-5-5
