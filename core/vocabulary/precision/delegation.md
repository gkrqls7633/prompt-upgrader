# 정밀 어휘: 위임 (DLG)

에이전트가 다른 에이전트에게 일을 나눌 때 기준과 전달 내용을 정하는 어휘다.

## V-DLG-01  위임 기준 / Delegate only when
- 상황: 에이전트가 하위 에이전트를 너무 많이 띄울 때
- 약한 표현: "필요하면 서브에이전트를 써"
- 강한 표현: "서로 결과를 기다리지 않는 독립 작업이 3개 이상일 때만 하위 에이전트에 맡긴다. 하위 에이전트는 맥락을 처음부터 읽어 비용이 크다."
- 효과가 있는 이유: 비용과 기준을 함께 주면 위임 판단이 일관된다
- 업무 예시: 코딩 - "모듈 3개를 동시에 조사할 때만 나눠 맡겨."
- 관련 규칙: R-AGT-001, R-TOL-005
- verified: 2026-11-21 / claude-opus-5-5

## V-DLG-02  브리핑 4요소 / Brief with
- 상황: 하위 에이전트에게 일을 맡길 때
- 약한 표현: "이거 조사해줘"
- 강한 표현: "하위 에이전트에게는 목표, 볼 범위와 보지 않을 범위, 끝난 기준, 돌려줄 형식을 함께 전달해."
- 효과가 있는 이유: 맥락 없는 하위 에이전트도 같은 기준으로 일하고, 결과를 합치기 쉬워진다
- 업무 예시: 데이터 - "지역별 분석을 맡길 때 같은 지표와 같은 표 형식을 지정해."
- 관련 규칙: R-AGT-002
- verified: 2026-11-21 / claude-opus-5-5

## V-DLG-03  반환 형식 고정 / Return format
- 상황: 여러 하위 결과를 합쳐야 할 때
- 약한 표현: "결과 알려줘"
- 강한 표현: "결과는 '발견, 근거 위치, 확신도(높음·중간·낮음)' 세 열의 표로만 돌려줘."
- 효과가 있는 이유: 형식이 같아야 상위 에이전트가 결과를 비교하고 합칠 수 있다
- 업무 예시: 문서 - "각 장의 요약을 같은 3줄 형식으로."
- 관련 규칙: R-AGT-002, R-OUT-001
- verified: 2026-11-21 / claude-opus-5-5

## V-DLG-04  결과를 확인한 뒤 보고 / Verify before reporting
- 상황: 하위 에이전트 결과를 그대로 사용자에게 전달하려 할 때
- 약한 표현: (언급 없음)
- 강한 표현: "하위 에이전트의 보고는 주장일 뿐이다. 핵심 결과는 직접 확인한 뒤 보고하고, 확인하지 못한 것은 표시해."
- 효과가 있는 이유: 하위 에이전트의 오류가 그대로 최종 결과에 섞이는 것을 막는다
- 업무 예시: 코딩 - "하위 에이전트가 고쳤다는 파일의 diff를 직접 보고 보고해."
- 관련 규칙: R-CMP-002, R-CMP-003
- verified: 2026-11-21 / claude-opus-5-5
