# 평가 실행 절차

이 스킬이 제대로 동작하는지(검출 평가)와, 어휘가 실제로 결과를 바꾸는지(효과 평가)를 측정한다. 규칙을 바꾼 뒤, 새 모델을 쓰기 전, refresh 중에 실행한다.

## 인자

| 인자 | 실행 범위 |
|---|---|
| (없음) | cases와 effects 둘 다 |
| `cases` | `evals/cases/` 21개 |
| `effects` | `evals/effects/` 10쌍 |
| `--model <모델ID>` | 결과 파일과 기록에 쓸 기준 모델. 없으면 현재 실행 중인 모델 ID |

## 검출 평가 (cases)

케이스마다 다음을 한다.

1. **실행.** 새 서브에이전트를 띄운다. 서브에이전트에게는 스킬 폴더의 `SKILL.md`를 읽고 따르라는 지시와, 케이스의 `mode`, `input`, `context`만 준다. `must_flag`, `must_not_flag`, `expect`는 보여주지 않는다. 답을 알면 평가가 의미 없기 때문이다.
   - `mode`가 `upgrade`이고 `바로`가 없는 케이스(질문형)는 첫 응답(질문과 추천)까지만 받는다.
2. **판정.** 서브에이전트의 출력을 받아 다음을 확인한다.
   - `must_flag`의 각 ID가 출력의 문제 목록, 점수 근거, 변경 요약 중 어딘가에 나오는가. 질문형 upgrade에서는 그 규칙이 다루는 정보를 질문했으면 검출로 본다.
   - `must_not_flag`의 ID(와일드카드 `R-LEG-*`, `F-*` 포함)가 문제로 지적되거나 추천되었는가. "모든 high severity 규칙"이면 `severity: high` 규칙 전체가 대상이다.
   - `expect`의 각 문장이 충족되었는가.
3. 서브에이전트는 동시에 여러 개 띄워도 된다. 케이스끼리 서로 의존하지 않는다.

## 효과 평가 (effects)

쌍마다 다음을 한다.

1. **실행.** A와 B를 각각 새 서브에이전트로 실행한다. 이 서브에이전트에게는 스킬을 쓰지 말고 프롬프트에 그대로 답하라고 한다. 측정 대상은 스킬이 아니라 어휘의 효과다.
2. **눈가림.** 두 출력을 무작위로 X, Y라고 이름 붙인다. 어느 쪽이 B인지 기록해 둔다.
3. **판정.** 별도 판정 서브에이전트에게 X, Y와 판정 기준만 주고, 각 출력이 기준을 몇 개 충족하는지 기준별로 예/아니오와 한 줄 근거를 받는다. 판정자에게는 어느 쪽이 어휘를 쓴 것인지 알려주지 않는다. 결과를 만든 쪽이 자기 결과를 채점하면 점수가 후해지기 때문이다.
4. **라벨 복원.** X, Y를 A, B로 되돌리고, B의 충족 수 - A의 충족 수를 계산한다. 2 이상이면 "효과 있음".

서브에이전트를 띄울 수 없는 도구에서는 각 프롬프트를 새 대화에서 실행하고, 판정은 사람이 판정 기준표로 한다. 결과 파일에 "사람 판정"이라고 적는다.

## 결과 파일

`evals/results/<YYYY-MM-DD>-<모델ID>-<종류>.md`에 저장한다. 종류는 `baseline`(refresh 2단계), `after`(refresh 4단계), `manual`(그 외).

```markdown
# 평가 결과 2026-11-21 · claude-opus-5-5 · manual
검출률 92% · 오탐 0 · 모범 점수 88 · 프레임 적중 6/6 · 효과 있음 8/10

## 검출 평가
| ID | 통과 | 누락된 must_flag | must_not_flag 위반 | expect | 메모 |
|---|---|---|---|---|---|
| C-01 | O | - | - | O | |
| C-02 | X | R-CTX-001 | - | O | 목적을 묻지 않음 |

## 효과 평가
| ID | 대상 | A 충족 | B 충족 | 차이 | 효과 |
|---|---|---|---|---|---|
| E-01 | F-CRT-01 | 1/3 | 3/3 | +2 | 있음 |

## 판정
통과 / 실패 (실패면 어떤 기준을 못 넘었는지)
```

요약 줄 계산:
- **검출률**: 모든 케이스의 `must_flag` ID 합계 중 검출된 비율
- **오탐**: `must_not_flag` 위반 건수 합계
- **모범 점수**: C-15, C-16 점수 중 낮은 것 (C-16은 원문 점수)
- **프레임 적중**: C-09~C-14 중 기대 프레임이 추천된 케이스 수
- **효과 있음**: E-01~E-10 중 "효과 있음" 수

## 통과 기준

다음을 모두 만족하면 통과다.
- 검출률 90% 이상
- 오탐 0건
- 모범 점수 85점 이상
- 프레임 적중 6/6

효과 평가는 통과 기준에 넣지 않는다. 효과 없음으로 나온 어휘는 해당 항목에 `- effect: none (<모델ID>, <날짜>)` 줄을 추가하고, refresh에서 수정 또는 폐기 후보로 다룬다. 어휘의 효과는 모델에 따라 달라질 수 있으므로, 실패가 아니라 갱신 신호로 본다.
