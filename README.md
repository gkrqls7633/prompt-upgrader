# prompt-upgrader

에이전트 지침을 검수하고, 모호한 프롬프트를 바로 쓸 수 있는 고수준 프롬프트로 바꿔 주는 AI 스킬이다. 규칙은 공식 프롬프트 엔지니어링 문서와 실제 평가 결과에 근거하고, 모델이 바뀌면 갱신하는 절차를 함께 갖고 있다.

## 해주는 일

- **지침 검수 (review)**: 에이전트 지침이나 시스템 프롬프트를 100점 만점으로 채점한다. 문제가 된 구절, 이유, 수정 문장을 보여준다.
- **프롬프트 고도화 (upgrade)**: "보고서 써줘" 같은 요청을 고수준 프롬프트로 바꾼다. 정보가 모자라면 기준을 채울 때까지 질문한 뒤에 만든다. 두 가지 어휘를 함께 쓴다. **프레임 어휘**(악마의 대변인, 프리모템 등)는 모델의 태도를 바꾸고, **정밀 어휘**(상위 5개, 결론 먼저, 완료 기준 등)는 결과의 형태를 정한다.
- **갱신과 평가 (refresh, eval)**: 공식 문서와 평가 결과를 대조해 낡은 규칙을 찾고, 변경안을 사람의 승인을 받아 반영한다.

## 1분 설치

준비물: `git`, 그리고 Claude Code(또는 Codex, Cursor). 설치 폴더(`~/.claude/skills`)가 없어도 아래 명령이 만들어 준다. `git`을 쓸 수 없는 환경이면 GitHub 저장소 화면의 Code > Download ZIP으로 받아 같은 위치에 `prompt-upgrader` 폴더로 풀면 된다.

### Claude Code

```bash
git clone https://github.com/gkrqls7633/prompt-upgrader.git ~/.claude/skills/prompt-upgrader
```

실행 중인 Claude Code 세션을 종료(`/exit`)하고 다시 실행한다. 입력창에 `/prompt`까지 치면 목록에 `prompt-upgrader`가 보이면 설치된 것이다.

**처음 해볼 것**: 평소 쓰던 짧은 요청 하나를 넣어 본다.
```text
/prompt-upgrader "이번 주 업무 보고 써줘"
```
질문이 나오면 아는 만큼 답한다. 정보가 충분해지면 개선된 프롬프트가 나온다.
결과 첫 줄이 `prompt-upgrader v1.1.0 · 규칙 기준일 ...`로 시작하면 정상이다.

**새 버전 받기**: 업데이트는 자동으로 되지 않는다. 대신 스킬을 쓸 때 GitHub에 새 버전이 있으면 결과 첫 줄 아래에 알려준다.

```text
prompt-upgrader v1.1.0 · 규칙 기준일 2026-11-21
새 버전 v1.2.0이 있습니다 (지금 v1.1.0). 받는 법: cd ~/.claude/skills/prompt-upgrader && git pull
```

이 줄이 보이면 아래처럼 받는다. 설치 방식에 따라 방법이 다르다.

| 설치 방식 | 새 버전 받는 법 |
|---|---|
| `git clone` (Claude Code, Codex, Cursor) | `cd ~/.claude/skills/prompt-upgrader && git pull` 한 번이면 세 도구 모두 바뀐다 |
| ZIP으로 받음 | 새 ZIP을 받아 폴더를 통째로 바꾼다 |
| ChatGPT 등 붙여넣기 | 새 `adapters/generic/system-prompt.md`를 다시 붙여 넣는다 |

버전 확인은 공개된 버전 번호 파일 하나만 읽고, 검수하는 내용은 어디에도 보내지 않는다. 사내망에서 GitHub가 막혀 있으면 확인을 건너뛰고 평소처럼 동작한다. Claude Code가 이 확인을 위해 인터넷 접근 허용을 물어보면 허용하면 된다. 받은 폴더 안의 파일을 직접 고쳤다면 `git pull`이 충돌할 수 있으니, 고치고 싶은 내용은 스킬 관리자에게 알린다.

### Codex

Claude Code와 같은 위치에 받아 둔다 (위의 `git clone` 명령). 그다음 프로젝트의 `AGENTS.md`에 `adapters/codex/AGENTS.md` 내용을 붙여 넣는다.

### Cursor

Claude Code와 같은 위치에 받아 둔다 (위의 `git clone` 명령). 그다음 `adapters/cursor/prompt-upgrader.mdc`를 프로젝트의 `.cursor/rules/` 폴더에 복사한다.

### ChatGPT, Gemini 등 (파일을 읽을 수 없는 도구)

`adapters/generic/system-prompt.md` 전체를 대화 첫 메시지나 시스템 프롬프트로 붙여 넣는다. 이 버전은 길이 때문에 핵심 규칙만 담고 있으며, refresh와 eval은 지원하지 않는다.

## 사용 예시

### 1. 에이전트 지침 검수

```text
/prompt-upgrader review
너는 회의록 요약 에이전트야.
회의 녹취록을 받으면 잘 요약해줘.
중요한 내용은 빠뜨리지 말고, 간단하게 정리해.
```

출력 요약:

```text
prompt-upgrader v1.1.0 · 규칙 기준일 2026-11-21

## 검수 결과: 39/100 (재작성)
| I4 완료 기준과 검증 | 0/15 | R-CMP-001 (완료 기준), R-CMP-002 (실제 검증 방법), R-CMP-003 (검증 못 한 것 보고) |
| I7 출력 형식       | 0/10 | R-OUT-001 (출력 형식 명시), R-OUT-003 (길이·분량·정렬 기준), R-CTX-003 (독자) |
...
1. [high] R-CLR-002 "회의 녹취록을 받으면 잘 요약해줘." / "간단하게 정리해."
   - 수정 제안: "회의록을 결정 사항, 담당자별 할 일, 미결 사항 세 구역으로 나눠 정리한다.
     각 구역은 5줄 이내로 쓴다."
```

근거로 나오는 `R-CMP-001` 같은 기호는 규칙 ID이고, 처음 나올 때 괄호 안에 뜻이 함께 나온다 (아래 "용어" 참고).

담당 업무와 보유 도구 목록을 함께 주면, 지침이 도구를 제대로 안내하는지까지 검사한다. 전체 출력은 [examples/review-meeting-summary-agent.md](examples/review-meeting-summary-agent.md)에 있다.

### 2. 모호한 요청 고도화 (한 질문씩 인터뷰)

```text
/prompt-upgrader "지난달 매출 데이터 분석해줘"
```

먼저 정보 충족도를 채점한다. 기준(총점 85점, 그리고 목표·맥락·완료 기준 항목)에 못 미치면, 질문 목록을 보여주고 **질문을 하나씩** 묻는다.

```text
## 정보 충족도: 22/100 (기준 85점)
| U2 (맥락과 이유) | 0/20 | 14 이상 | 누락: 분석 결과를 어디에 쓰는지 (R-CTX-001 목적과 결과물의 쓰임) |
...
## 질문 목록 (하나씩 여쭙니다)
1. 분석으로 알고 싶은 것 · 2. 결과를 쓰는 곳 · 3. 완료 기준

## 질문 1/3: 지난달 매출 데이터를 분석해서 무엇을 알고 싶으신가요?
(a) 원인 (b) 추이 (c) 상품·채널·지역별 비교 (d) 기타
예시 답: "지난달 매출이 그 전달보다 왜 줄었는지 원인을 알고 싶다"
```

답이 부족하면 무엇이 빠졌는지 말하고 같은 질문을 좁혀서 다시 묻는다. 모르면 "넘어가기"라고 답하면 된다.

```text
2번 답("회의용")으로는 아직 부족합니다 (U2 (맥락과 이유) 0 → 6/20, 기준 14).
어떤 회의인지, 그 회의에서 이 결과로 무엇을 정하는지가 빠졌습니다.

## 질문 2/3 (다시): 그 회의에서 이 분석을 보고 무엇을 결정하나요?
(a) 예산 증감 (b) 목표 수정 (c) 담당자·대응책 지정 (d) 결정 없이 공유만
```

모든 질문이 끝나고 기준을 넘으면 개선본이 나온다. 개선본에는 답한 내용만 들어가고, 스킬이 더 넣으면 좋겠다고 본 것은 "추가로 넣을 만한 것"에 따로 나온다. 질문 목록을 두 번 돌아도 기준에 못 미치면 "계속 답하기"와 "[확인 필요]를 둔 기준 미달 초안 받기" 중에서 고른다. 전체 흐름은 [examples/upgrade-data-request.md](examples/upgrade-data-request.md)에 있다.

### 3. 프레임 어휘 추천

```text
/prompt-upgrader "내가 이번에 직장인 대상의 명상 앱을 기획했어. 구독료는 월 1만원이고, 아침마다 5분짜리 오디오를 제공해. 이 기획안 어때? 피드백해줘."
```

인터뷰 첫 응답부터 요청의 의도에 맞는 프레임 어휘를 추천한다.

```text
## 질문 목록 (하나씩 여쭙니다)
1. 원하는 피드백의 종류 · 2. 피드백을 쓰는 곳 · 3. 완료 기준

## 추천 프레임 (기준을 넘으면 적용)
- F-CRT-01 (악마의 대변인): 기획안을 결정 전에 검증하는 요청이라 칭찬 위주의 무난한 조언 대신 허점을 공격하게 만든다. ...
- F-CRT-04 (회의적인 투자자): 월 1만원 구독 모델이라 수익성을 숫자로 따져 묻는 관점이 맞을 수 있다. ...
```

전체 출력은 [examples/upgrade-frame-devils-advocate.md](examples/upgrade-frame-devils-advocate.md)에 있다.

## 명령어

### 모든 사용자

| 명령 | 하는 일 |
|---|---|
| `/prompt-upgrader review` + 지침 | 지침을 채점하고 문제점과 수정 문장을 보여준다 |
| `/prompt-upgrader upgrade` + 요청 | 정보 충족도를 채점하고, 기준(85점)을 넘을 때까지 질문을 하나씩 한 뒤 개선본을 만든다 |
| `/prompt-upgrader` + 아무 텍스트 | 지침처럼 보이면 review, 짧은 요청이면 upgrade |

슬래시 명령이 없는 도구에서는 "prompt-upgrader로 이 지침 review 해줘"처럼 자연어로 요청한다.

**개선본 쓰는 법**: 코드 블록 안의 내용을 복사해, `[대괄호]` 부분을 실제 내용으로 바꾼 뒤 원래 쓰던 에이전트에 붙여 넣는다. 채울 내용이 없는 줄은 지운다.

### 스킬 관리자 (규칙을 갱신하는 담당자)

| 명령 | 하는 일 |
|---|---|
| `/prompt-upgrader refresh` | 공식 문서와 평가로 규칙 갱신 변경안을 만든다 |
| `/prompt-upgrader eval` | 스킬 자체의 품질을 평가한다 |
| `/prompt-upgrader eval effects --model <모델ID>` | 특정 모델에서 어휘 효과만 평가한다 |

## 용어

| 용어 | 뜻 |
|---|---|
| 프레임 어휘 | 모델의 태도를 바꾸는 말. 예: "악마의 대변인"(일부러 반대 입장에서 허점을 공격하는 역할), "프리모템"(이미 실패했다고 가정하고 원인을 찾는 방법) |
| 정밀 어휘 | 결과의 형태를 정하는 말. 예: "상위 5개", "결론 먼저", "다음이 모두 참이면 완료" |
| R-CMP-001 같은 번호 | 규칙 ID. 지적의 근거가 된 규칙이다. 몰라도 쓰는 데 지장 없고, 궁금하면 `core/rules/`에서 찾는다 |
| I1~I8, U1~U6 | 채점 항목. I는 에이전트 지침용, U는 사용자 요청용 |
| effect: none | 그 모델에서는 이 어휘의 효과가 작게 측정됐다는 기록 |

## 문제 해결

| 증상 | 확인할 것 |
|---|---|
| `/prompt-upgrader`가 목록에 없다 | `~/.claude/skills/prompt-upgrader/SKILL.md` 파일이 있는지 확인하고, Claude Code를 완전히 종료한 뒤 다시 실행한다 |
| 결과 첫 줄에 버전이 `v0.0.0`으로 나온다 | 받은 폴더에 `VERSION` 파일이 있는지 확인한다. ZIP으로 받았다면 폴더 구조가 그대로인지 본다 |
| 결과 끝에 "재검증 필요"가 나온다 | 규칙이 낡았을 수 있다는 신호다. 스킬 관리자에게 알린다 |
| 검수 중 모델이 응답을 거부한다 | 지침에 "생각 과정을 응답에 다 적어" 같은 문장이 있으면 그럴 수 있다. 그 문장을 빼고 다시 검수한다 |

## 구조

```
prompt-upgrader/
├── SKILL.md            Claude Code 진입점
├── core/               모든 도구가 함께 쓰는 본문 (원본은 여기 하나)
│   ├── PROTOCOL.md     모드 판별과 공통 원칙
│   ├── modes/          review, upgrade, refresh, eval 절차
│   ├── rubric.md       채점 기준 (지침용, 사용자 프롬프트용)
│   ├── rules/          규칙 48개 (11개 카테고리)
│   ├── vocabulary/
│   │   ├── precision/  정밀 어휘 43개 (9개 상황)
│   │   └── frames/     프레임 어휘 20개 (7개 의도)
│   └── sources.md      근거 문서와 핵심 주장 스냅샷
├── adapters/           Codex, Cursor, 붙여넣기용
├── examples/           실제 실행 출력
├── evals/              검출 평가 22개, 효과 평가 10쌍, 결과 기록
├── refresh/            갱신 변경안 기록
├── MAINTAINING.md      관리자용 갱신 절차
└── CHANGELOG.md
```

규칙 하나는 이런 모양이다. 모든 규칙에 근거 문서와 마지막 검증일이 붙는다.

```markdown
### R-EMP-002  절대 금지어 대신 범위와 이유를 쓴다
- scope: claude
- severity: high
- source: S-04
- verified: 2026-11-21 / claude-opus-5-5
- Before: 절대 파일을 삭제하지 마.
- After: 파일을 삭제하기 전에는 승인을 받는다. 복구할 수 없는 작업이기 때문이다.
```

## 버전과 갱신

모든 결과의 첫 줄에는 스킬 버전과 규칙 기준일이 나온다.

```text
prompt-upgrader v1.1.0 · 규칙 기준일 2026-11-21
```

규칙 기준일은 이번 결과에 쓰인 규칙 중 가장 오래 전에 검증된 날짜다. 프롬프트 모범 사례는 모델과 함께 바뀌기 때문에, 오늘 맞는 규칙도 몇 달 뒤에는 낡을 수 있다. 검증일이 90일을 넘은 규칙이 쓰이면 결과 끝에 "재검증 필요"가 표시된다.

이 표시가 보이거나, 회사가 쓰는 모델이 바뀌면 관리자가 refresh를 실행한다. refresh는 공식 문서를 다시 읽고 평가를 돌려 변경안을 만든다. 실제 반영은 사람이 승인한 항목만 하고, 평가를 통과해야 버전이 올라간다. 단계별 명령은 [MAINTAINING.md](MAINTAINING.md)에 있다.

v1.0.0의 평가 결과(claude-opus-5-5)는 다음과 같다. 첫 기준선은 검출률 89%였고, 보정 두 번을 거쳐 검출률 100%, 오탐 0건, 잘 쓴 지침 점수 96점이 됐다. 회차별 기록은 [evals/results/](evals/results/)에 있다.

## 규칙과 어휘 추가하기

1. `core/rules/`나 `core/vocabulary/`의 해당 파일에 기존 항목과 같은 형식으로 추가한다.
2. [MAINTAINING.md](MAINTAINING.md)의 "규칙이나 어휘를 직접 추가할 때"에 있는 구조 검사 명령을 실행한다.
3. `/prompt-upgrader eval`로 평가를 통과하는지 확인한다.
4. `VERSION`과 `CHANGELOG.md`를 갱신하고 PR을 연다.

이 저장소는 공개 저장소다. 예시와 평가 케이스에는 사내 정보 없이 가상의 에이전트만 쓴다.

## 한계

- 규칙은 기준일 시점의 공식 문서와 평가에 근거한 모범 사례다. 모델이 바뀌면 낡을 수 있으므로 결과 머리말의 기준일을 확인한다.
- 점수는 판단을 돕는 수단이지 정답이 아니다. 같은 입력도 실행마다 몇 점씩 달라질 수 있다.
- 프레임 어휘의 효과는 모델마다 다르다. v1.0.0 평가에서는 10개 중 3개(프리모템, 파인만 기법, 스틸맨)만 claude-opus-5-5에서 뚜렷한 차이를 보였다. 나머지는 어휘 없이도 모델이 기준을 대부분 충족했다. 해당 항목에는 `effect: none`이 기록되어 있고, 추천할 때 함께 알려준다.
- "생각 과정을 응답에 전부 적어"처럼 추론 과정 출력을 요구하는 지침은 검수 도중 모델의 안전장치에 막힐 수 있다. 이 패턴 자체가 R-LEG-004에서 경고하는 위험이다.
- 붙여넣기용 버전(ChatGPT 등)은 핵심 규칙만 담고 있어 Claude Code 버전보다 검수 범위가 좁다.
- 이 스킬은 별도 서버로 데이터를 보내지 않는다. 다만 검수할 지침과 요청은 지금 쓰고 있는 AI 도구(모델)에 그대로 전달되므로, 사내 정보를 넣을지는 회사의 AI 도구 사용 정책을 따른다.
