# 예시: 에이전트 지침 검수 (review)

가상의 회의록 요약 에이전트 지침을 검수한다. 담당 업무와 도구 목록은 주지 않았다.

## 입력

```text
너는 회의록 요약 에이전트야.
회의 녹취록을 받으면 잘 요약해줘.
중요한 내용은 빠뜨리지 말고, 간단하게 정리해.
```

## 실행

```text
/prompt-upgrader review
(위 지침을 붙여 넣는다)
```

## 출력

prompt-upgrader v1.0.0 · 규칙 기준일 2026-11-21

## 검수 결과: 58/100 (재작성)

| 항목 | 점수 | 근거 |
|---|---|---|
| I1 역할, 미션, 이유 | 2/15 | R-CTX-001, R-FIT-001, R-CTX-003: 요약의 쓰임, 범위 밖 업무, 독자가 없음 |
| I2 도메인 판단 기준 | 12/15 | R-FIT-004: "중요한 내용"을 가르는 기준 없음 |
| I3 도구와 스킬 사용 지침 | 15/15 | 미제공: 도구 목록이 없어 검사하지 않음 |
| I4 완료 기준과 검증 | 2/15 | R-CMP-001, R-CMP-002, R-CMP-003 |
| I5 경계와 승인 | 10/10 | 해당 없음: 외부 행동이 없는 요약 에이전트 |
| I6 작업 절차 | 10/10 | 해당 없음: 단일 작업 |
| I7 출력 형식 | 2/10 | R-OUT-001, R-OUT-003 |
| I8 표현 품질 | 5/10 | R-CLR-002: "잘 요약해줘", "간단하게" |

## 문제 목록 (심각도 순)

1. **[high] R-CLR-002** "회의 녹취록을 받으면 잘 요약해줘." / "간단하게 정리해."
   - 이유: "잘", "간단하게"는 기준이 없어 요약 길이와 구성이 매번 달라진다. 받는 사람이 결과를 예측할 수 없다.
   - 수정 제안: "요약은 결정 사항, 담당자별 할 일, 미결 사항 세 구역으로 나누고 각 구역은 5줄 이내로 쓴다."
2. **[high] R-OUT-001** 누락: 출력 형식
   - 이유: 문단인지 글머리표인지, 어떤 구역으로 나누는지 정해지지 않아 회의록을 공유하거나 다른 시스템에 옮기기 어렵다.
   - 수정 제안: "출력은 마크다운으로 `## 결정 사항`, `## 할 일`(담당자 | 할 일 | 기한 표), `## 미결 사항` 순서로 쓴다. 해당 내용이 없는 구역은 '없음'으로 적는다."
3. **[high] R-CTX-001** 누락: 요약을 누가, 어디에, 무엇에 쓰는지
   - 이유: 회의에 빠진 사람이 따라잡기 위한 요약인지, 후속 업무를 배분하기 위한 요약인지에 따라 무엇을 남길지가 달라진다.
   - 수정 제안: "요약은 회의에 참석하지 못한 팀원이 5분 안에 읽고 자기 할 일과 결정된 내용을 파악하는 데 쓴다."
4. **[high] R-CMP-001** 누락: 완료 기준
   - 이유: 어떤 조건을 만족해야 요약이 끝난 것인지 없어서, 모델이 "중요한 것을 다 담았다"고 스스로 판단할 근거가 없다.
   - 수정 제안: "녹취록에서 확정된 결정과 담당자가 정해진 할 일이 모두 요약에 들어 있고, 각 구역이 길이 제한 안에 있으면 완료다."
5. **[high] R-FIT-001** "너는 회의록 요약 에이전트야."
   - 이유: 무엇을 하는지만 있고 하지 않는 일과 범위 밖 요청을 받았을 때의 행동이 없다. 회의 내용에 대한 의견, 메일 작성 요청 등이 들어오면 임의로 처리한다.
   - 수정 제안: "너는 회의 녹취록을 요약하는 에이전트다. 녹취록에 있는 내용만 정리하고, 회의 내용에 대한 평가나 후속 메일 작성은 하지 않는다. 그런 요청을 받으면 요약 범위 밖이라고 알린다."
6. **[high] R-CMP-002** 누락: 요약 내용을 녹취록과 대조하는 검증
   - 이유: 요약에서 가장 큰 사고는 녹취록에 없는 결정이나 잘못된 담당자를 만들어 내는 것이다. 대조 지시가 없으면 이를 잡을 단계가 없다.
   - 수정 제안: "출력하기 전에 결정 사항과 할 일 하나하나가 녹취록의 어느 발언에서 나왔는지 확인한다. 근거 발언을 찾지 못한 항목은 지운다."
7. **[medium] R-FIT-004** "중요한 내용은 빠뜨리지 말고"
   - 이유: 무엇이 중요한지 기준이 없다. 회의 요약에서 좋은 결과와 나쁜 결과를 가르는 기준(결정, 할 일, 기한을 남기고 잡담과 반복 논의는 버림)이 지침에 있어야 한다.
   - 수정 제안: "중요한 내용은 확정된 결정, 담당자와 기한이 있는 할 일, 결론 없이 끝난 쟁점이다. 인사, 잡담, 같은 주장의 반복은 요약에 넣지 않는다."
8. **[medium] R-CTX-003** 누락: 요약을 읽을 사람
   - 이유: 독자의 배경지식에 따라 용어 설명이나 맥락을 얼마나 붙일지가 달라진다.
   - 수정 제안: "독자는 같은 팀원이지만 회의에 참석하지 않은 사람이다. 팀 안에서 쓰는 용어는 그대로 쓰되, 회의 중 처음 나온 안건은 한 줄로 배경을 붙인다."
9. **[medium] R-CMP-003** 누락: 녹취록에서 확인되지 않는 정보의 처리
   - 이유: 담당자나 기한이 말로 정해지지 않은 경우, 녹취가 끊기거나 화자가 표시되지 않은 경우에 모델이 추측으로 채울 수 있다.
   - 수정 제안: "담당자나 기한이 녹취록에 없으면 '미정'으로 적고 추측하지 않는다. 알아들을 수 없거나 화자를 알 수 없는 구간은 요약 끝에 '확인 필요'로 따로 적는다."
10. **[medium] R-OUT-003** "간단하게 정리해."
    - 이유: 분량과 정렬 기준이 없다. 1시간 회의와 10분 회의의 요약 길이를 어떻게 할지 모델이 정할 수 없다.
    - 수정 제안: "전체 요약은 A4 한 쪽(약 20줄) 이내로 쓴다. 할 일은 기한이 빠른 순서로 정렬한다."

## 규칙 외 관찰
- "중요한 내용은 빠뜨리지 말고"와 "간단하게 정리해"가 서로 당긴다. 길이 제한과 반드시 남길 항목 중 무엇이 우선인지 정해 두지 않으면, 모델은 회의마다 다른 쪽을 택한다. 반드시 남길 항목(결정, 할 일)을 먼저 정하고 나머지에 길이 제한을 거는 식으로 우선순위를 적는 것이 좋다.

## 제공되지 않은 정보
- 담당 업무: 제공하면 R-FIT-001의 범위 정의를 실제 업무에 맞게 검사할 수 있다.
- 보유 도구 목록: 도구 목록 미제공. 제공하면 I3와 R-FIT-002, R-FIT-003을 검사할 수 있고 정확도가 올라간다.
- 대상 모델: 명시되지 않아 Claude 기준 규칙을 모두 적용했다.
