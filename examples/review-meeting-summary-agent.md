# 예시: 에이전트 지침 검수 (review)

가상의 회의록 요약 에이전트 지침을 검수한다. 담당 업무와 도구 목록은 주지 않았다.

## 입력

```text
너는 회의록 요약 에이전트야.
회의 녹취록을 받으면 잘 요약해줘.
중요한 내용은 빠뜨리지 말고, 간단하게 정리해.
```

## 실행

```text
/prompt-upgrader review
(위 지침을 붙여 넣는다)
```

## 출력

prompt-upgrader v1.1.0 · 규칙 기준일 2026-11-21

## 검수 결과: 39/100 (재작성)

|---|---|---|
| I1 역할, 미션, 이유 | 2/15 | 역할 한 문장("너는 회의록 요약 에이전트야")만 있음. R-CTX-001 (목적과 결과물의 쓰임): 누락: 요약을 누가 어디에 쓰는지. R-FIT-001 (담당 업무 범위 정의): 누락: 하지 않는 일과 범위 밖 요청 처리. R-CTX-002 (규칙에 이유 붙이기): 규칙 2개에 이유 없음 |

## 문제 목록 (심각도 순)

1. **[high] R-CLR-002** "회의 녹취록을 받으면 잘 요약해줘." / "간단하게 정리해."
   - 이유: "잘", "간단하게"는 기준이 없어 요약 길이와 구성이 녹취록마다 달라진다. 이 지침의 핵심 지시가 둘 다 모호어다.
   - 수정 제안: "회의록을 결정 사항, 담당자별 할 일, 미결 사항 세 구역으로 나눠 정리한다. 각 구역은 5줄 이내로 쓴다."
2. **[high] R-OUT-001** 누락: 출력 형식
   - 이유: 표인지, 글머리표인지, 문단인지 정해져 있지 않아 결과를 메일이나 협업 도구에 바로 옮기기 어렵다.
   - 수정 제안: "출력은 마크다운으로 `## 결정 사항`, `## 할 일`, `## 미결 사항` 순서로 쓴다. 할 일은 `| 할 일 | 담당자 | 기한 |` 표로 쓰고, 녹취록에 없는 칸은 '미정'으로 둔다."
3. **[high] R-CMP-001 (완료 기준)** 누락: 완료 기준
   - 이유: 어떤 조건을 만족하면 요약이 끝났는지 없어, "빠뜨리지 말 것"을 확인할 방법이 없다.
   - 수정 제안: "녹취록에서 합의된 결정과 담당자가 정해진 할 일이 모두 요약에 들어 있으면 완료다."
4. **[high] R-CMP-002 (실제 검증 방법)** 누락: 요약을 원본과 대조하는 절차
   - 이유: 요약은 발언을 잘못 옮기거나 합의되지 않은 내용을 결정으로 적는 실수가 흔하다. 원본 대조 단계가 없으면 그대로 나간다.
   - 수정 제안: "요약을 내기 전에 결정 사항과 할 일마다 녹취록의 해당 발언을 다시 찾아 내용과 담당자가 맞는지 확인한다."
5. **[high] R-CTX-001 (목적과 결과물의 쓰임)** 누락: 요약을 누가 어디에 쓰는지
   - 이유: 참석자 공유용인지, 불참자 보고용인지, 경영진 보고용인지에 따라 무엇이 중요한지가 달라진다.
   - 수정 제안: "요약은 회의 직후 참석자와 불참자에게 공유되어 각자 맡은 할 일을 확인하는 데 쓰인다."
6. **[high] R-FIT-001 (담당 업무 범위 정의)** 누락: 하지 않는 일과 범위 밖 요청 처리
   - 이유: 요약만 하는지, 의견 평가나 회의 개선 제안까지 하는지 경계가 없어 요청 밖 내용이 섞일 수 있다.
   - 수정 제안: "너는 회의 녹취록을 요약하는 에이전트다. 녹취록에 있는 내용만 정리하고, 발언에 대한 평가나 개선 제안은 하지 않는다. 녹취록 외 작업을 요청받으면 요약만 담당한다고 안내한다."
7. **[medium] R-FIT-004** "중요한 내용은 빠뜨리지 말고"
   - 이유: 무엇이 중요한지 기준이 없어 모델이 임의로 고른다. 회의 요약에서 결과를 가르는 것은 결정, 할 일, 담당자, 기한이다.
   - 수정 제안: "중요한 내용은 합의된 결정, 담당자와 기한이 있는 할 일, 결론이 나지 않은 쟁점이다. 잡담, 반복된 의견, 결론 없이 끝난 아이디어는 넣지 않는다."
8. **[medium] R-CMP-003** 누락: 녹취록이 불명확할 때의 처리
   - 이유: 녹취록은 화자 누락, 오인식, 끊긴 문장이 흔하다. 처리 방법이 없으면 모델이 담당자나 기한을 추측해 채운다.
   - 수정 제안: "담당자나 기한이 녹취록에서 확인되지 않으면 추측하지 말고 '미정'으로 적는다. 알아듣기 어려운 구간은 요약 끝 `## 확인 필요`에 시간이나 앞뒤 발언과 함께 적는다."
9. **[medium] R-OUT-003** "간단하게 정리해."
   - 이유: 분량과 정렬 기준이 없어 1시간 회의와 10분 회의의 요약 길이를 예측할 수 없다.
   - 수정 제안: "전체 요약은 20줄 이내로 쓴다. 결정 사항은 회의에서 나온 순서로, 할 일은 기한이 빠른 순서로 정렬한다."
10. **[medium] R-CTX-003** 누락: 요약을 읽을 사람
    - 이유: 독자의 배경지식에 따라 용어 설명과 맥락의 양이 달라진다.
    - 수정 제안: "요약은 회의에 참석하지 않은 팀원이 읽고 자기 할 일과 기한을 바로 알 수 있게 쓴다."

나머지:
- **[medium] R-CTX-002**: "빠뜨리지 말고", "간단하게"에 이유가 없음. 각 규칙 뒤에 왜 필요한지 한 문장을 붙인다.
- **[medium] R-EMP-003**: "빠뜨리지 말고"는 금지형이다. "결정 사항과 할 일은 모두 포함한다"처럼 포함할 것을 긍정형으로 쓴다.

## 규칙 외 관찰
- "중요한 내용은 빠뜨리지 말고"와 "간단하게 정리해"가 서로 당기는 지시인데 우선순위가 없다. 분량이 부족할 때 무엇을 먼저 줄일지(예: 미결 사항의 배경 설명부터 줄이고 결정과 할 일은 유지) 정해 두면 충돌이 사라진다.
- 녹취록이 어떤 형태로 들어오는지(화자 표기 여부, 타임스탬프 유무) 지침에 없다. 형태를 알면 화자별 할 일 추출 같은 지시를 더 구체적으로 쓸 수 있다.

## 제공되지 않은 정보
- 담당 업무: 제공하면 R-FIT-001의 범위 제안을 실제 업무에 맞게 고칠 수 있다.
- 보유 도구 목록: 제공하면 I3와 R-FIT-002 (언급 도구와 보유 도구 일치), R-FIT-003 (보유 도구마다 사용 지침)을 검사할 수 있다. 공유나 메일 발송 도구가 있다면 I5도 다시 본다.
- 대상 모델: 명시가 없어 Claude 기준 규칙을 모두 적용했다.
