# 예시: 프레임 어휘 즉시 변환 (upgrade 바로)

기획안 피드백 요청에 '악마의 대변인' 프레임을 적용한다. 프레임 어휘는 모델의 태도를 칭찬 위주에서 공격적 검토로 바꾸고, 정밀 어휘(개수, 관점, 형식, 완료 기준)가 결과를 바로 쓸 수 있는 형태로 만든다.

## 입력

```text
내가 이번에 직장인 대상의 명상 앱을 기획했어. 구독료는 월 1만원이고, 아침마다 5분짜리 오디오를 제공해. 이 기획안 어때? 피드백해줘.
```

## 실행

```text
/prompt-upgrader upgrade 바로 "내가 이번에 직장인 대상의 명상 앱을 기획했어. ..."
```

## 출력

prompt-upgrader v1.0.0 · 규칙 기준일 2026-11-21

## 추천 프레임
- **F-CRT-01 악마의 대변인**: 기획안을 출시 전에 검증하려는 피드백 요청이라서. 주의: 장점은 다루지 않는 프레임인데 원문의 "어때?"는 균형 평가일 수도 있다. 그래서 개선본은 대안 문형("강점을 먼저 짚고, 그다음 공격해")을 썼다. 이 모델(claude-opus-5-5)에서는 효과가 작게 측정됐다. 효과는 함께 쓰는 정밀 어휘에서 주로 나온다.
- **F-CRT-04 회의적인 투자자**: 구독료 월 1만원이라는 수익 모델이 핵심이라서, 피드백의 중심을 수익성 숫자로 옮기고 싶을 때 쓴다. 주의: 수익보다 사용자 경험이나 콘텐츠 품질을 보고 싶다면 맞지 않는다.

## 개선된 프롬프트
```text
너는 이제부터 아래 기획안의 악마의 대변인이다. 이 기획안이 출시 후 1년 안에 실패한다고 가정하고 공격해.

<기획안>
- 대상: 직장인
- 서비스: 명상 앱
- 가격: 월 구독료 1만원
- 핵심 기능: 매일 아침 5분짜리 명상 오디오 제공
- 추가 정보: [타깃 직장인 세부 조건, 경쟁 앱 조사 결과, 차별점 등 있으면 붙여넣기. 없으면 이 줄 삭제]
</기획안>

이 피드백은 [출시 전에 계속 진행할지, 고칠지 결정하는 데] 쓴다. 그래서 칭찬보다 약점을 찾는 데 분량을 쓴다.

1. 먼저 이 기획안의 강점 2개를 각 한 줄로만 짚어.
2. 그다음 가격, 경쟁(무료 대안 포함), 지속 사용률, 수익성 네 관점에서 치명적인 허점 5개를 심각도 순으로 제시해.
3. 허점마다 허점, 공격 논리, 심각도(상/중/하), 검증할 가장 싼 방법 하나 네 열의 표로 정리해.
4. 기획안에 적힌 사실과 네 추정(시장 규모, 이탈률 등)은 구분해서 표시해.

허점 5개가 모두 서로 다른 원인을 다루고, 각각 검증 방법이 일주일 안에 적은 비용으로 해볼 수 있는 것이면 끝이다.
```

## 변경 요약 (원문 63점 → 개선본 95점)
| 변경 전 | 변경 후 | 근거 |
|---|---|---|
| 이 기획안 어때? | 악마의 대변인으로 공격해 (강점 2개는 한 줄씩만) | R-CLR-001, F-CRT-01 |
| (목적 없음) | 출시 전 진행 여부 결정에 쓴다 | R-CTX-001 |
| 기획 내용이 문장 속에 섞임 | `<기획안>` 태그로 분리 | R-STR-001 |
| 피드백해줘 | 4개 관점, 치명적 허점 5개, 심각도 순 | R-CLR-002, V-SCP-03, R-OUT-003 |
| (형식 없음) | 허점, 공격 논리, 심각도, 검증 방법 네 열의 표 | R-OUT-001, V-FMT-01 |
| (없음) | 출시 후 1년 안에 실패한다고 가정 | F-CRT-01, V-SCP-05 |
| (없음) | 기획안의 사실과 추정 구분 | V-EVD-04 |
| (완료 기준 없음) | 원인이 겹치지 않는 허점 5개 + 일주일 안에 해볼 수 있는 검증 방법 | R-CMP-001, V-DON-01 |

원문 감점 내역:
- U1 목표와 행동 12/20: "이 기획안 어때?" (R-CLR-001, -5), "피드백해줘" 기대 수준 불명 (R-CLR-004, -3)
- U2 맥락과 이유 15/20: 누락: 피드백을 어디에 쓰는지 (R-CTX-001, -5)
- U3 입력 자료 12/15: 기획 내용이 지시문과 섞여 있음 (R-STR-001, -3)
- U4 범위와 제약 10/15: "피드백해줘" 관점과 개수 기준 없음 (R-CLR-002, -5)
- U5 출력 형식과 독자 4/15: 누락: 출력 형식 (R-OUT-001, -5), 분량과 정렬 기준 (R-OUT-003, -3), 독자 (R-CTX-003, -3)
- U6 완료 기준 10/15: 누락: 완료 조건 (R-CMP-001, -5)

개선본 감점: U2 15/20. 목적이 `[대괄호]` 가정으로만 채워져 있어서 실제 목적을 넣기 전까지 R-CTX-001을 부분 충족으로 봤다.

## 가정
- 피드백의 목적은 출시 전에 진행 여부를 결정하는 것이라고 가정했다. 투자 유치용이면 F-CRT-04 회의적인 투자자로 바꾸는 편이 낫다.
- 원문의 "어때?"가 균형 평가일 수 있어 강점 2개를 한 줄씩 넣었다. 약점만 원하면 1단계를 지운다.
- 경쟁 앱 조사나 타깃 세부 정보는 없다고 보고 `[추가 정보]` 빈칸으로 두었다.
- 피드백을 읽는 사람은 기획자 본인이라서 독자를 따로 지정하지 않고, 바로 판단할 수 있게 표 형식으로 정했다.

## 재검증 필요
- 없음

## 읽는 법

개선된 프롬프트 코드 블록을 그대로 복사해 쓴다. [대괄호]는 채워 넣을 빈칸이다. 추천 프레임에 '효과가 작게 측정됨'이 붙어 있으면, 이 모델은 프레임 없이도 어느 정도 비판적으로 답한다는 뜻이다. 이때 결과를 바꾸는 것은 주로 개수, 관점, 형식 같은 정밀 어휘다.
